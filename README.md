# Telegram Test Bot

Telegram-бот на PHP для проведения тестирования пользователей.

Пользователь запускает тест, отвечает на вопросы с вариантами ответа и
получает итоговый результат в зависимости от количества набранных
баллов.

Проект написан без ООП: логика разделена между отдельными PHP-файлами.

## Возможности

-   запуск теста через кнопку Telegram;
-   вопросы с вариантами ответа в виде обычных текстовых сообщений;
-   начисление баллов за каждый ответ;
-   последовательный переход между вопросами;
-   расчёт и отправка итогового результата;
-   хранение пользователей, результатов и ответов в SQLite;
-   несколько прохождений теста одним пользователем;
-   админ-панель для просмотра пользователей и их
    прохождений;
-   просмотр ответов и результата отдельного прохождения;
-   автоматическая очистка старых результатов и незавершённых тестов;
-   защита от повторной обработки одного Telegram update по `update_id`.

## Назначение основных файлов

### `public/webhook.php`

Точка входа для входящих обновлений Telegram. Проверяет HTTP-метод и
корректность JSON, загружает настройки и передаёт обновление в
`handleUpdate()`.

### `src/update_handler.php`

Маршрутизирует входящие сообщения: обрабатывает `/start`, запуск теста,
ответы на вопросы и действия администратора.

Основные функции:

-   `handleUpdate()`
-   `handleMessage()`

### `src/test_service.php`

Содержит логику прохождения теста: загрузку вопросов, запуск, отправку
вопросов, обработку ответов, начисление баллов и завершение прохождения.

Основные функции:

-   `getTests()`
-   `startTest()`
-   `sendQuestion()`
-   `goToPreviousQuestion()`
-   `processAnswer()`

### `src/result_service.php`

Работает с завершёнными прохождениями: сохраняет результаты и ответы,
получает список пользователей и прохождений, а также определяет итоговый
вердикт по количеству баллов.

Основные функции:

-   `getResultByScore()`
-   `saveResult()`
-   `getResultsByUsername()`
-   `getUsersWithResults()`
-   `getUserResults()`
-   `getResultAnswers()`

### `src/user_storage.php`

Работает с текущим состоянием пользователя: получает и сохраняет
состояние, удаляет временную запись и хранит данные о выбранном
администратором пользователе.

Основные функции:

-   `getUser()`
-   `saveUser()`
-   `deleteUser()`
-   `updateUserState()`
-   `updateAdminTarget()`
-   `getAdminTarget()`

### `src/admin.php`

Содержит логику администратора: проверку Telegram ID администратора,
показ панели, выбор пользователя и просмотр его прохождений.

Основные функции:

-   `escapeTelegramHtml()`
-   `isAdmin()`
-   `showAdminPanel()`
-   `showAdminUsers()`
-   `handleAdminUsername()`
-   `handleAdminTestSelection()`

### `src/telegram.php`

Содержит функции для обращения к Telegram Bot API:

-   `TG_sendMessage()`
-   `removeKeyboard()`

### `src/database.php`

Создаёт PDO-подключение к SQLite через `getDatabase()`. Таблицы должны
быть созданы отдельно с помощью SQL-схемы из `database/schema.sql`.

### `src/cleanup.php`

Скрипт очистки старых данных. Его следует запускать по расписанию через
Cron.

Текущая логика: - удаление завершённых результатов старше 30 дней и
связанных с ними ответов; - удаление незавершённых тестов и временных
ответов старше одного дня; - удаление обработанных Telegram updates
старше 30 дней.

## Данные теста

### `data/tests.json`

Содержит содержимое теста в формате JSON:

-   идентификатор теста;
-   вопросы;
-   варианты ответов;
-   количество баллов за каждый ответ.

Вопросы и варианты ответов отделены от PHP-логики. Благодаря этому
содержание теста можно менять в JSON-файле, не переписывая обработчик
прохождения.

## База данных

Проект использует SQLite. Файл базы данных создаётся в
`data/database.sqlite` при подключении PDO, но таблицы автоматически не
создаются.

SQL-структура находится в `database/schema.sql`.

В базе используются таблицы:

-   `users` --- текущее состояние пользователей;
-   `results` --- завершённые прохождения теста;
-   `answers` --- ответы, сохранённые для конкретного результата;
-   `current_answers` --- временные ответы во время прохождения;
-   `processed_updates` --- идентификаторы уже обработанных обновлений
    Telegram.

`results` и `answers` хранят историю завершённых прохождений. `users` и
`current_answers` используются для текущего состояния и незавершённого
теста.

## Установка и настройка

### Требования

-   PHP с расширениями PDO SQLite и cURL;
-   Composer;
-   SQLite;
-   публичный HTTPS-адрес для работы Telegram Webhook.

### 1. Получить проект и установить зависимости

В корневой папке проекта выполнить:

``` bash
composer install
```

Composer установит зависимости и создаст папку `vendor/`.

### 2. Создать файл `.env`

Скопировать `.env.example` в `.env` и указать собственные значения:

``` dotenv
TELEGRAM_TOKEN=your_telegram_bot_token
ADMIN_ID=123456789
```

`ADMIN_ID` --- Telegram ID администратора. Если администраторов
несколько, укажи их через запятую:

``` dotenv
ADMIN_ID=123456789,987654321
```

### 3. Создать базу данных и таблицы
Перед запуском бота необходимо создать файл базы данных и таблицы, а также убедиться, что папка `data/` существует и доступна PHP для записи.

1. Создайте пустой файл `database.sqlite` в папке `data/`, если он ещё не существует.
2. Откройте PhpStorm и перейдите во вкладку **Database**.
3. Нажмите `+` → `Data Source` → `SQLite`.
4. В поле `File` укажите путь к файлу `data/database.sqlite`.
5. Нажмите **Test Connection**, затем **Apply** и **OK**.
6. Откройте файл `database/schema.sql` в редакторе PhpStorm.
7. В верхней панели редактора выберите созданное подключение SQLite.
8. Выполните SQL-скрипт с помощью кнопки **Run** (зелёный треугольник).

После выполнения скрипта в базе данных должны появиться таблицы:

- `users`
- `results`
- `answers`
- `current_answers`
- `processed_updates`

**Альтернативный способ — через SQLite CLI**

Если установлен SQLite CLI, можно выполнить SQL-скрипт из корневой папки проекта:

```bash
sqlite3 data/database.sqlite < database/schema.sql
```
После успешного выполнения база данных готова к работе.


### 4. Настроить Telegram Webhook

Webhook должен указывать на публичный HTTPS-адрес файла:

``` text
https://YOUR_DOMAIN/webhook.php
```

При размещении проекта важно настроить корневую директорию сайта на
папку `public/`. Тогда URL `/webhook.php` будет соответствовать файлу
`public/webhook.php`.

Для локальной разработки можно использовать ngrok или другой
HTTPS-туннель.


## Локальный запуск

Из корневой папки проекта запустить встроенный сервер PHP:

``` bash
php -S localhost:8000 -t public
```

Для получения публичного HTTPS-адреса во время локального тестирования
можно запустить ngrok в другом терминале:

``` bash
ngrok http 8000
```

После этого настрой Telegram Webhook на выданный ngrok HTTPS-адрес с
путём `/webhook.php`.

## Очистка старых данных

На хостинге настрой Cron на регулярный запуск файла:

``` text
src/cleanup.php
```

Например, скрипт можно запускать один раз в сутки. Сроки хранения данных
задаются внутри `cleanup.php` и не зависят от частоты запуска Cron.

## Безопасность и публикация

Перед публикацией проекта убедись, что в Git не попали:

-   `.env` с токеном Telegram;
-   `data/database.sqlite` и резервные копии базы;
-   логи;
-   `vendor/`.

Для исключения таких файлов используется `.gitignore`. Файл
`.env.example` можно публиковать, если в нём указаны только названия
переменных и демонстрационные значения.

Если настоящий токен Telegram когда-либо попал в публичный
Git-репозиторий, его необходимо заменить через BotFather. Простого
удаления файла из последнего коммита недостаточно: секрет мог
сохраниться в истории Git.
